# ServiceWatchdog

Небольшое Windows-приложение, которое следит за службами и программами и поднимает их, если они упали.

Вы задаёте список правил: «служба `Spooler` должна работать» или «`C:\Tools\bot.exe --port 8080` должен быть запущен».
ServiceWatchdog проверяет каждое правило с его собственным интервалом и, если цель не работает, запускает её заново.
Приложение живёт в трее и может стартовать вместе с Windows.

## Возможности

- **Любое количество правил.** Каждое правило — это либо **служба Windows**, либо **процесс (.exe)**.
- **Службы:** выбор из списка установленных служб с поиском. Остановленная служба запускается через `ServiceController.Start()`, ожидание запуска — до 30 секунд.
- **Процессы:** путь к `.exe` и необязательные аргументы командной строки. Рабочая папка — папка исполняемого файла.
- **Свой интервал проверки** для каждого правила (в секундах, минимум 1).
- **Включение/отключение** правила без удаления.
- **Кнопка «Проверить сейчас»** — для выбранного правила или для всех сразу.
- **Журнал событий** в главном окне (последние 200 записей): что упало, что перезапущено, какие ошибки.
- **Работа в трее.** Крестик и сворачивание прячут окно в трей, мониторинг продолжается. Выход — через меню значка в трее.
- **Автозапуск при входе в Windows** через Планировщик заданий, с правами администратора и без UAC-запроса.
- **Один экземпляр.** Повторный запуск показывает сообщение, что приложение уже работает.

## Требования

- Windows 10 или Windows 11, x64.
- Права администратора. Приложение запрашивает их через UAC при запуске: без них большинство служб запустить нельзя.
- Для готового exe из раздела [Releases](../../releases) ничего устанавливать не нужно — .NET уже внутри.
- Для сборки из исходников — [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

## Установка

### Вариант 1. Готовый exe

1. Откройте страницу [Releases](../../releases) и скачайте `ServiceWatchdog.exe` из последнего релиза.
2. Положите файл в постоянную папку, например `C:\Program Files\ServiceWatchdog\`.
   Автозапуск ссылается на путь к exe, поэтому не запускайте файл из «Загрузок», если потом планируете его переместить.
3. Запустите `ServiceWatchdog.exe` и подтвердите запрос UAC.

> Windows SmartScreen может предупредить о неизвестном издателе: exe не подписан цифровой подписью.
> Нажмите «Подробнее» → «Выполнить в любом случае» или соберите exe сами из исходников.

### Вариант 2. Сборка из исходников

```powershell
git clone https://github.com/synorexx-eng/ServiceWatchdog.git
cd ServiceWatchdog\ServiceWatchdog
dotnet build -c Release
```

Результат: `ServiceWatchdog\bin\Release\net8.0-windows\ServiceWatchdog.exe`.
Для такого exe на компьютере нужен [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0).

### Вариант 3. Один exe без зависимостей

```powershell
cd ServiceWatchdog\ServiceWatchdog
dotnet publish -c Release -r win-x64 --self-contained true
```

Результат — один файл (~70 МБ, .NET runtime внутри, сжат):
`ServiceWatchdog\bin\Release\net8.0-windows\win-x64\publish\ServiceWatchdog.exe`.
Этот файл можно скопировать на любой ПК с Windows 10/11 x64.

## Использование

1. Запустите приложение и подтвердите UAC.
2. Нажмите **«Добавить»**.
3. Выберите тип правила:
   - **Служба Windows** — введите имя службы (поле «Имя службы» в `services.msc`, не отображаемое имя) или нажмите **«Выбрать…»** и найдите службу в списке.
   - **Процесс (приложение)** — укажите путь к `.exe` (кнопка **«Обзор…»**) и, если нужно, аргументы командной строки.
4. Задайте интервал проверки в секундах и нажмите **«Сохранить»**.
5. Если нужно, включите **«Запускать при входе в Windows»**.
6. Закройте окно — приложение уйдёт в трей и продолжит работу.

Управление из трея: двойной клик по значку открывает окно, правый клик — меню «Открыть» / «Выход».

Статусы в таблице:

| Статус | Значение |
|---|---|
| Работает | Цель запущена, действий не нужно |
| Остановлена (…) — запуск… / Не запущен — запуск… | Цель не работала, идёт запуск |
| Работает (перезапущена) / Запущен | Запуск прошёл успешно |
| Служба не найдена | Неверное имя службы |
| Таймаут запуска службы | Служба не перешла в состояние Running за 30 секунд |
| Ошибка: … / Не удалось запустить: … | Текст ошибки Windows |

## Как это работает

- Таймер раз в секунду смотрит, каким правилам пора делать проверку. Проверки одного правила не пересекаются.
- **Служба** считается работающей в состояниях `Running` и `StartPending`. В остальных состояниях приложение вызывает `Start()`.
- **Процесс** ищется по имени exe без расширения (`Process.GetProcessesByName`).
  Если процесс с таким именем уже есть — даже запущенный из другой папки — правило считается выполненным.
- **Автозапуск** создаёт задачу `ServiceWatchdog` в Планировщике заданий: триггер «При входе в систему»,
  наивысшие права, без лимита времени, запуск с ключом `--minimized`.
  Ярлык в папке «Автозагрузка» здесь не подходит: Windows не запускает оттуда программы, которым нужны права администратора.

## Параметры запуска

| Ключ | Действие |
|---|---|
| `--minimized` | Запуск сразу в трей, без показа окна |

## Где хранятся данные

Правила и настройки хранятся в `%AppData%\ServiceWatchdog\settings.json`. Пример:

```json
{
  "Rules": [
    {
      "Name": "Диспетчер печати",
      "Type": 0,
      "ServiceName": "Spooler",
      "ProcessPath": "",
      "ProcessArguments": "",
      "IntervalSeconds": 30,
      "Enabled": true
    },
    {
      "Name": "Мой бот",
      "Type": 1,
      "ServiceName": "",
      "ProcessPath": "C:\\Tools\\bot.exe",
      "ProcessArguments": "--port 8080",
      "IntervalSeconds": 10,
      "Enabled": true
    }
  ],
  "StartWithWindows": true,
  "StartMinimized": false
}
```

`Type`: `0` — служба, `1` — процесс. `StartMinimized: true` всегда запускает приложение в трей.

## Удаление

1. Снимите галочку **«Запускать при входе в Windows»** — задача в Планировщике удалится.
2. Выйдите из приложения через меню трея **«Выход»**.
3. Удалите `ServiceWatchdog.exe` и папку `%AppData%\ServiceWatchdog`.

## Структура проекта

```
ServiceWatchdog/
├── App.xaml(.cs)                 — старт, один экземпляр, ключ --minimized
├── MainWindow.xaml(.cs)          — таблица правил, журнал, трей
├── RuleEditWindow.xaml(.cs)      — добавление и редактирование правила
├── ServicePickerWindow.xaml(.cs) — выбор службы из списка
├── Models/                       — WatchRule, RuleType, AppSettings
└── Services/
    ├── WatchdogEngine.cs         — проверка и перезапуск служб и процессов
    ├── SettingsService.cs        — чтение и запись settings.json
    └── StartupService.cs         — автозапуск через Планировщик заданий
```

Стек: C#, .NET 8, WPF (+ WinForms для значка в трее).
